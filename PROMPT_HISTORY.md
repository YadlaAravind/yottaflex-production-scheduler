# AI Prompt History – YottaFlex Production Scheduler

## 1. Purpose

This document records the use of AI tools during the development of the YottaFlex Production Scheduling System.

AI assistance was used for problem understanding, database design, backend and frontend development, debugging, validation, and documentation.

## 2. AI Tool Usage

| AI Tool | Purpose |
|---|---|
| ChatGPT | Technical guidance, problem analysis, architecture, debugging, validation, and documentation |

## 3. Representative Prompt Records

The following prompts summarize the major categories of AI assistance used during development. They are representative summaries and are not claimed to be exact copies of every prompt submitted.

### Prompt 1 – Understanding the Problem

Help me understand the production scheduling problem and identify the major requirements, entities, constraints, and expected deliverables.

### Prompt 2 – Database Design

Help me design a relational database schema for production scheduling, including products, machines, routings, routing steps, production orders, materials, inventory lots, and machine calendars.

### Prompt 3 – Scheduling Constraints

Explain how to handle machine availability, operation precedence, machine downtime, labor shifts, material availability, and sequence-dependent changeovers in a production scheduling system.

### Prompt 4 – Backend Development

Help me understand and debug a Python FastAPI backend using SQLAlchemy models and REST API endpoints for production scheduling.

### Prompt 5 – Frontend Development

Help me build a React dashboard that displays production analytics, machine utilization, production schedules, and unscheduled operations using backend API data.

### Prompt 6 – Validation

Help me validate production schedules for machine downtime conflicts, operation precedence, material availability, machine calendars, and changeover constraints.

### Prompt 7 – Debugging

Help me investigate scheduling errors and identify possible improvements without modifying the original database or applying unverified schedule repairs.

### Prompt 8 – Documentation

Help me prepare project documentation, including a README, database data dictionary, validation results, known limitations, and setup instructions.

The developer is responsible for reviewing, understanding, testing, and verifying the submitted implementation, including its scheduling logic, database design, API behavior, and known limitations.
